# Common Pitfalls

## 1. The fernignore regeneration trap

Most of the tree (`reference.md`, `Types/`, `Organization/`, `OrganizationDetails/`, `Exceptions/`, most of `Core/`) is **generated by Fern** and overwritten on the next generation run. Only files listed in `.fernignore` survive — notably `Wrapper/`, `Core/RawClient.cs`, `MyOrganizationApiClient.Internal.cs`, `*.Custom.props`, and the test `Unit/Wrapper/` dir. If you edit a non-fernignored file, your change will vanish on the next release. Fix belongs in the generator; discuss via an issue/PoC PR.

## 2. Multi-target framework differences

The SDK targets `net8.0`, `net9.0`, `netstandard2.0`, and `net462`. Watch for:
- **`DateOnly`** — not available on `net462`/`netstandard2.0`; the project uses `Portable.System.DateTimeOnly` there and defines `USE_PORTABLE_DATE_ONLY`. `Core/DateOnlyConverter.cs` is compiled only under the portable path.
- **`System.Text.Json`** — pulled in as a package (`10.0.9`) only for pre-`net8.0` targets; it's in-box on net8/net9.
- Verify a change builds under **all** targets, not just your local default. CI builds every TFM.

## 3. `Optional<T>` null semantics

By default, `null`-valued fields are omitted from the JSON payload. To send an explicit `null`, assign `Optional<T?>.Of(null)` — not a bare `null`. Getting this wrong silently drops the field from the request body.

## 4. Domain vs BaseUrl

`MyOrganizationClient` builds the base URL as `https://{Domain}/my-org/v1`. A `Domain` containing a scheme (`https://`) or a path/slash throws `ArgumentException`. If you set `BaseUrl` explicitly it wins and is used as-is — callers must then include the `/v1` segment themselves.

## 5. Token providers own their own HTTP path

Token acquisition (`ClientCredentialsTokenProvider`) is separate from the API `RawClient`. The `Auth0-Client` telemetry header is injected in `RawClient` for API calls; don't assume token-endpoint calls share the same pipeline.
